## Corrections exposed by real data

The first run held publication because presentation validated raw trusted spawn
height guesses as exact grounded recovery feet. Authority already resolves those
guesses using shared support and clearance checks. Startup preparation now exposes
those resolved feet to presentation, retaining metadata and its identity inputs.
A sloped-spawn regression proves raw guesses fail while resolved feet agree with
authority and pass presentation validation.

The next run published successfully but failed the independent admission-identity
oracle. Default JSON decimal parsing changed one source spawn height by one f64
bit compared with correctly rounded parsing. Workspace serde_json now enables
`float_roundtrip` on the same locked version. A regression reproduces typed and
Value parsing, serialization and exact IEEE bits for actual source heights.
Identity comparison remains exact. Previously misparsed decimal metadata can
therefore acquire a corrected identity; regenerate matching local sessions.
Wire/ALPN 11, identity domains, engine/plugin pins and lockfile remain unchanged
by this correction. Earlier rejected runs are retained separately as failures.

## Bounded lifecycle evidence

The ordinary Bevy client records at most 64 lifecycle events with root entity
IDs, descendant mesh counts, visibility, asset counts and at most 1,024 shared
image paths/handle IDs per event. A truncation flag prevents treating incomplete
traces as complete evidence. Events cover preparation, hidden staging, publication,
settling and rejected/superseded candidates. Settling waits two seconds after
pending preparation and live-physics readiness finish; this is an observation
window, not a universal asset collection deadline or memory guarantee.

Diagnostic capture now waits for exact chunk permission confirmation and both
clients' readiness markers. Both peers remain alive until both captures finish.
This avoids an early peer departure invalidating an asymmetric-load comparison.
The default smoke timings remain when diagnostic barriers are absent.
Delayed bound-geometry checks independently derive complete cells from indexed
contributor envelopes: the delayed actor remains in initial coverage while the
ready actor enters newly complete coverage. Package-owner maxima alone cannot
define that boundary for overlapping town geometry. A negative-cell/nonlocal
contributor regression protects this oracle.

An explicit bound-geometry oracle independently counts reachable source GLB
primitives and checks hidden-to-visible staging, unchanged retained root IDs,
and unchanged retained image handles. Existing green-floor pixel assertions
remain the default for original streaming fixtures. Actual-town added props can
be outside the camera; these checks do not claim pixel fidelity for that prop.

Per-case process sampling uses the existing Linux RSS/PSS/DRM recorder. It spans
the entire concurrent two-client debug run; maxima are not phase-specific,
additive RAM/VRAM totals, cold-load measurements or latency percentiles.
Broader retirement/reversal/supersession/asymmetric failure cases, sustained
performance, default adoption and native Windows remain separate gates. No whole
source task, phase, production streaming or MMO-scale claim follows.

reports, 160 ordinary Rust tests, three private-source tests and 91 Python tests,

image assets remain 383. Normal publication observes 1.814–1.823 seconds; the
delayed peer observes 6.930 seconds including its injected five seconds. These
are single debug observations with active validation, not performance targets.
