# P2-14 — approved regenerated sprites in the game

Scope: integrate the approved `content/ui/sprites-v3` artwork into the native
client's existing frontend and game interface. Prerequisites are the qualified
sprite export, native login/roster/customisation, shared Bevy controls, preference
resources and existing inventory/quest/party/map/combat screens. This slice adds
presentation only; authority, input admission, account and gameplay protocols
remain unchanged. The zone editor retains its separate authoring theme.

The shared `ui_theme` embeds all nine atlas pages and the versioned manifest.
Sprites select explicit atlas rectangles; slicing uses the manifest's texture-pixel
insets and 0.25 maximum corner scale (four texture pixels per UI unit). Images use
sRGB, straight alpha and linear sampling. The client does not read the regeneration
build folder or Downloads for these sprites. The retained `--fantasy-ui` launcher
option still validates its legacy source for backwards compatibility.

Shared panels, title plates, input fields, ordinary buttons, roster rows, tabs,
close controls, inventory/action slots, checkboxes and sliders use the new art.
Disabled/pressed/selected/focused/hover/default states select the corresponding
exported sprite, with disabled taking precedence. Roster focus no longer draws a
square outline. Text, hit areas, accessible names, keyboard navigation and actual
`InteractionDisabled` remain live Bevy controls; decoration ignores picking.

Item/ability icons, health/mana/casting/experience fills, party bars and the minimap
rim also use regenerated artwork. Existing server values still determine fill
width, item identity, counts, cooldowns and selections. Item-image substitutions
are presentation placeholders: stone/shard, token/coins, wand/crystal,
pelt/leather and orders/book. They do not change item definitions. The minimap
terrain and player direction continue to be generated by the existing map system.

Twelve supplemental standalone gold icons in `content/ui/theme/standalone-v3`
match the approved account bust. Lock, eye, gear, support, power, graphics,
controller, keyboard, interface, accessibility, language and rotation have transparent
exteriors and no button backing. Exact built-in image-generation prompts and
source/final hashes are in `generation.json`. Deterministic alpha cleanup removes
unwanted detached shadow remnants and normalises bounds to a 128px canvas.
The rejected UI ZIP/contact sheet and earlier icon sheets are not used.
Existing illustrated login, character courtyard, Millhaven loading screen and
licensed Liberation fonts remain.

Username, password, character-name and chat fields share the 48px default height
and form-relative width. Login icons reserve padding without changing outer field
size; the eye remains within the password box. Eye and Settings/Support/Exit
glyphs brighten on hover, while username/lock glyphs stay static. Disabled graphics
checkboxes share Vertical Sync's 22px frame, 32px row and 17px label; disabled and
live dropdowns share the 32px height, arrow position and content insets. Disabled
controls retain their disabled sprites and input blocking. Both settings panels
reserve the remaining height for tab content and keep Restore Defaults / Apply /
OK / Cancel in a fixed bottom row, independent of the selected tab. Section titles use
border-box artwork and 32px horizontal text clearance. Slider focus brightens the
diamond instead of drawing a square outline around the track. Character-name
format feedback appears inline as `- invalid name!`, using the existing shared
validator, and clears immediately for empty or valid input. The parser and server
name policy are unchanged; unrelated account/server errors remain visible.

An invisible bounded area over the preview owns primary-pointer horizontal drag;
it does not cover the roster or creation fields. Mirrored gold curved-arrow sprites
sit beside the feet as the rotation cue. Zoom out / Reset view / Zoom in buttons
sit below the preview; zoom is bounded to 75–130%, with the limit button disabled.
Reset restores zoom and yaw. Release ends a drag, and focused Left/Right keys
remain available. Empty accounts and Login show no model or preview controls.
The normal gameplay facing/camera is untouched. Three additional transparent
sprites were generated with built-in image_gen and cleaned deterministically;
exact prompts/hashes are in `content/ui/theme/standalone-v3/preview-generation.json`.

Acceptance: complete client tests; formatting and denied-warning Clippy; native
login, error recovery, empty/full roster, creation/selection and same-window world
entry; checkbox/slider mouse and keyboard; settings Apply/Cancel; inventory,
quest/ability/party/menu/chat-log screens; multiple window sizes and GPU diagnostics.
The initial full native run passed both fresh and restarted accounts, including
1920×1080 and tiled 1720×700 windows, with no Vulkan diagnostics. Visual review
then caught parent text covered by a child field image, content-box title art
colliding with labels and retained procedural outlines on empty slots. Follow-up
uses a border-box image on the TextInput entity beneath its own glyphs, border-box
title art with content padding, and removes obsolete static-slot outlines. The
native qualifier explicitly checks visible typed-name pixels after entry. Its
observation lookup excludes covered login links while a settings modal is open,
and waits for the requested controls instead of racing a page transition.

The foreground login/roster/customisation layout fills each actual client window.
The background covers it with proportional, centred cropping; no fixed 16:9
letterbox determines control positions. Login panel width is capped at 560 logical
pixels, and the rotation control stays inside the bottom edge at short heights.
Active/pressed text is white, with disabled grey retaining precedence.
