# Bounded runtime chunk capacity

Qualified capacity slice, 2026-10-20. P1-03/P1-06/P1-08/P1-10/P2-06/P2-07/P2-08,
execution-order row 5. Prerequisites are [verified actual-content budgets](CHUNK_BUDGETS.md),
contributor-complete coverage and paired publication. This qualifies a bounded
runtime ceiling and original fixtures. Actual-town native adoption/world edges
and whole task/phase completion remain open.

## Implemented contract

- `chunks::MAX_RESIDENT` is 32, justified by the conservative 26-package town
  demand. Each session keeps its explicit smaller budget; previous fixtures
  remain at their original budgets. The static collider ceiling stays 8,192,
  finite index ceiling 64 and bounded local query frame unchanged.
- Wire/ALPN version 11 rejects the previous contract; Renet protocol IDs derive
  from that version. Readiness, acknowledgements and offers accept at most 32
  strictly sorted unique checked global chunk addresses. Invalid i64 addresses
  reject before applying a report. The datagram ceiling remains 1,200 bytes;
  input/snapshot limits and independent bounded queues are unchanged.
- World identity domain `theia-authoritative-chunk-world-v3\0` adds the session
  budget as LE u16 immediately after the index digest, followed by the unchanged
  spawn/fall-plane/initial-set encoding. Different budgets cannot admit under
  the same identity. Index identity and query-frame independence are unchanged.
- One background candidate remains the limit. It may add multiple standard GLB
  roots; matching old roots and shared image handles are retained. Retirement
  still requires exact authority acknowledgement plus a post-application
  snapshot, protected presentation/recovery coverage and matching live Avian.
- Offline index authoring accepts a selected `--resident-limit` from 1 through
  32, default 32. A tighter limit remains usable for small fixtures. The real
  partition publisher retains its four-provider automatic metadata gate until
  actual-world adoption/world-edge policy qualifies. The default launcher stays
  the monolithic town revision 2 at 30 Hz.

Actual Rust full-width-header control encodings fit the conservative size bounds
926 / 979 / 955 bytes for readiness / wrapped acknowledgement / wrapped offer.
A real secure UDP case transmits a 32-entry offer, readiness, exact acknowledgement,
withdrawal and regrant at a negative billion-metre origin, with acknowledged
movement and zero recoveries. This is bounded loopback evidence, not capacity
under Internet impairments or MMO populations.

## Executed checks

- Fresh fmt, denied-warning workspace/all-target Clippy, build and **154 workspace
  Rust tests** pass; three private tests are ignored by default and separately
  pass. A final 27-test library run requalifies the input-negative cases after
  replacing their hardcoded old versions with the current version. **70 Python
  tests** pass (66 asset plus four GLB).
- Full-capacity disk/Avian tests load 32 original packages at zero and signed
  billion-metre positions in shifted query frames. Every loaded floor supports
  queries, the indexed but unloaded 33rd cell remains closed, gravity remains
  unconstrained, and over-budget replacement leaves the old generation intact.
  The 36-provider envelope case rejects the 32-provider limit.
- Private town authority loads ten initial packages and publishes all 26 against
  a live actor without changing its position; 90 subsequent ticks have zero
  recoveries. Warm-cache samples: initial preparation 1,525.138 ms, off-step
  candidate preparation 1,563.392 ms and publication 11.433 ms. These are single
  samples with one actor/four trusted spawns, not scheduling percentiles, cold
  loading or client/GPU memory evidence. The staged session is explicitly opt-in
  at `build/chunk-capacity-town-runtime-stage`, budget 26; original packages,
  candidate stage and launcher remain unchanged.
- Both private house routes pass at 20/30/60 Hz with zero recoveries; the private
  monolithic shared-image package verifies all 488 dependencies.
- **Eight actual two-client native cases**, 16 reports, pass on AMD Radeon RX
  7900 XTX / RADV NAVI31 Vulkan with active Khronos validation. They cover 32
  initial standard roots sharing one image, six new required providers in one
  delayed publication, the same at negative billion-metre positions with a
  separate client query frame, failed-image retention, graybox, town and farmhouse
  routes, and Quinn ALPN 11. The delayed peers hide uncovered remotes for 78 and
  92 frames respectively. Retained roots, exact retirement barriers, shared image
  bindings, matching live Avian generation, ground/camera and two-pawn pixels
  stay checked. A publication screenshot was visually inspected.

Evidence is in [validation](VALIDATION.md). No native Windows, crowd/soak or
actual-town chunk rendering/memory qualification is claimed.
